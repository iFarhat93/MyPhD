The Silicon Ladder

CPU, GPU, FPGA and ASIC are four ways to implement a computation. They differ in how much of the computation is fixed when the chip is designed and how much is controlled by a program at run time. This page presents each platform in turn: the problem it was created to solve, how it works, where it is efficient, and how the four are combined in one system. Level 0

One principle: the cost of generality

A computer performs arithmetic, moves data, and controls the order of operations. The four platforms differ in how much of that control is performed by a program at run time and how much is fixed in the circuit.

The principle

In a general-purpose processor, every operation is described by an instruction. The instruction must be fetched from memory, decoded and scheduled, and its operands must be moved between memory, caches and registers. This control and data movement consume far more energy than the arithmetic itself.

In an application-specific circuit, the sequence of operations is fixed in the wiring. No instructions are fetched, and data moves directly from one arithmetic unit to the next. The four platforms form a scale between these two extremes. A GPU is a processor that executes one instruction on many data elements at once, which divides the instruction overhead among them. An FPGA is a reconfigurable circuit: it has no instructions, but its generic logic blocks and wiring are larger and slower than custom ones. An ASIC is the custom circuit itself.

Three sources of speed. A computation can be accelerated by a higher clock frequency, by executing more operations in parallel, or by removing work that does not contribute to the result. Clock frequency stopped increasing around 2004 because of power dissipation. Parallelism requires work that can be divided. Specialisation removes the overhead of generality, but requires the computation to be known at design time. The scale from CPU to ASIC is a progression along this third option.

Where the energy goes in a processor

Arithmetic is a small part of the energy budget. A 32-bit addition costs about 0.1 pJ. Fetching the operands from DRAM costs about 640 pJ, several thousand times more. The control overhead of a complete instruction (fetch, decode, register access) is of the order of tens of picojoules.

Hameed et al. (2010) measured the consequence for video coding. An H.264 encoder running on a general-purpose processor consumed about 500 times the energy of an ASIC implementing the same encoder. SIMD and VLIW extensions reduced the gap by about a factor of 10. The remaining factor of 50 required custom datapaths that pass data between units without instructions or memory accesses. Video coding is therefore a representative case for this scale, and it is the reason the thesis works at its application-specific end.

Summary
  1. Arithmetic is cheap; instructions and data movement are expensive.
  2. Each step from CPU to ASIC removes run-time control and gains efficiency at the cost of flexibility.
  3. For a video encoder the measured energy gap between a processor and an ASIC is about 500 times.
Level 1 · CPU

The CPU: a stored program, one instruction at a time

A central processing unit executes one sequence of instructions per core. Because the program is stored in memory as data, the same processor can execute any program.

How it works

A core repeats one cycle: fetch the next instruction from memory, decode it, execute it, write the result. Several mechanisms make this cycle fast. A pipeline overlaps the stages of consecutive instructions. Caches keep recently used data close to the core, because main memory is slow. A branch predictor guesses the outcome of conditional jumps so that fetching does not stall. Out-of-order execution runs independent instructions ahead of a stalled one. SIMD units apply one instruction to 4 to 16 values at once.

All of these mechanisms serve a single instruction stream and reduce its latency. For workloads that apply the same operation to millions of elements, they add cost without adding throughput.

The founding decision (1945): the stored program. The ENIAC was programmed by rewiring, which took days. John von Neumann's report on the EDVAC proposed holding the program in the same memory as the data, so that a new task required a new program rather than a new machine. This is the origin of general-purpose computing, and of the instruction overhead described in Level 0.

History

  1. 1945Stored-program architecture (von Neumann): fetch, decode and execute instructions held in memory.
  2. 1971Intel 4004: the first microprocessor, a complete CPU on one chip, 2,300 transistors, designed for a calculator.
  3. 1980s–90sPipelining; caches, because DRAM speed fell behind processor speed; superscalar execution (Pentium, 1993); out-of-order execution (Pentium Pro, 1995); SIMD extensions (MMX 1997, SSE, AVX).
  4. 2004The power limit: Intel cancels a 4 GHz Pentium 4. Smaller transistors no longer reduced power per transistor proportionally (the end of Dennard scaling, 1974–2004). Clock frequencies have stayed near 3–5 GHz since.
  5. 2006Multicore processors become standard: more cores rather than faster cores. Parallel programming becomes necessary for performance.
  6. 2010sThe CPU integrates specialised blocks: AES encryption (2010), the Quick Sync video codec (2011), graphics units, AI units. A CPU package is now a small system on chip.

Strengths

  • General computation: operating systems, compilers, databases, protocols, control logic.
  • Irregular code in which each step depends on the result of the previous one.
  • Low latency for a single task; mature languages, debuggers and libraries.
  • The host role: a CPU controls every other platform in a system.

Limitations

  • Low throughput per watt on regular, data-parallel work such as pixels or matrices.
  • At most tens of cores; memory bandwidth of about 50–100 GB/s.
  • Most energy goes to instruction overhead and data movement rather than arithmetic.
  • Execution time varies with cache and predictor state, so it is not deterministic.
In video coding and in the thesis

Software encoders (x264, x265) and decoders (VTM, OpenVVC) run on CPUs. They are appropriate for files encoded offline and for research. For live video with a fixed frame rate, the thesis notes that a CPU cannot reach a standard's best quality in real time. CPUs still run the control software of the partner's encoder, including the logic that selects which four ALF filter sets the hardware decision engine evaluates for each picture.

Summary
  1. The program is stored as data; this is what makes a CPU general purpose.
  2. Pipelines, caches and predictors serve one instruction stream; they are overhead for bulk data processing.
  3. The 2004 power limit shifted the industry toward multiple cores and specialised accelerators.
Level 2 · GPU

The GPU: one instruction, thousands of data elements

A graphics processing unit executes the same instruction on many data elements at once. It accepts a higher latency per task in exchange for a much higher throughput.

How it works

Rendering a 3D scene applies the same short program to millions of vertices and pixels, which are independent of each other. A GPU organises threads in groups of 32 that execute one instruction in lockstep on 32 data elements (NVIDIA's term is SIMT). Thousands of such groups are kept resident. When one group waits for memory, the scheduler issues another. Latency is hidden by the number of threads rather than by large caches or prediction, and the memory bandwidth is 10 to 30 times that of a CPU.

The limitation is divergence. If the threads of a group take different branches, both branches are executed in turn and the inactive threads idle. Regular computations run at full efficiency; irregular ones do not.

Two decisions (1999–2007): throughput over latency, then programmability. The GeForce 256 (1999) moved the geometry stage into hardware. Programmable shaders (2001) made the per-pixel computation a program. Unified shader cores and CUDA (2006–2007) allowed that program to be arbitrary. The last step made the GPU the main platform for scientific computing and, after 2012, for deep learning.

History

  1. 19963dfx Voodoo: a fixed-function 3D accelerator for PC games; geometry was still computed on the CPU.
  2. 1999NVIDIA GeForce 256, marketed as the first "GPU": transform and lighting computed in hardware.
  3. 2001GeForce 3: programmable vertex and pixel shaders.
  4. 2006–07Unified shader cores (G80) and CUDA: general-purpose computing on GPUs.
  5. 2012AlexNet, trained on two consumer GPUs, wins the ImageNet competition. GPUs become the standard platform for neural networks.
  6. 2012–17The GPU integrates specialised blocks of its own: NVENC/NVDEC video codec engines (2012), tensor cores for matrix arithmetic (2017), ray-tracing units.

Strengths

  • Data-parallel work: graphics, matrix multiplication, neural networks, physics simulation, image filtering.
  • Throughput of tens of teraflops; memory bandwidth of terabytes per second.
  • Programmable: new algorithms are deployed as software (CUDA, OpenCL, shaders).

Limitations

  • Divergent branches and irregular memory access leave most lanes idle.
  • Small or latency-critical tasks are dominated by the PCIe transfer and kernel launch time.
  • Power consumption of 150–700 W per card excludes fanless or battery-powered devices.
  • Sequential stages such as CABAC entropy coding offer no parallelism.
In video coding

Shader programs are suitable for scaling, colour conversion and filtering. The encoders and decoders inside GPUs (NVENC/NVDEC, AMD VCN, Intel Quick Sync) are not shader programs: they are fixed-function blocks, small ASIC designs placed on the GPU or CPU die. Encoding "on the GPU" therefore uses an application-specific circuit hosted on a programmable one. The thesis designs blocks of the same kind, for a chip whose entire purpose is the codec.

Summary
  1. Groups of threads execute in lockstep; efficiency is highest when every thread does the same work.
  2. Latency is hidden by thread count and memory bandwidth, not by caches.
  3. GPU video encoding is performed by ASIC-style blocks inside the GPU.
Level 3 · FPGA

The FPGA: a circuit that can be reconfigured

A field-programmable gate array does not execute instructions. The designer describes a circuit; tools map it onto a grid of configurable logic blocks and programmable wires; at power-up the chip is configured as that circuit.

How it works

The fabric consists of look-up tables, flip-flops and a mesh of wires with programmable switches. A 6-input look-up table stores a 64-entry truth table and therefore implements any Boolean function of 6 inputs. A bitstream sets every table and every switch. After configuration, data flows through logic and registers on each clock edge, as in an ASIC, and all parts of the circuit operate concurrently.

The generic blocks and switches are larger and slower than custom logic. FPGAs therefore include fixed hard blocks: block RAM, DSP slices for multiply-accumulate operations, high-speed transceivers and, in some families, ARM processor cores. The thesis mapped its first transform design onto an Intel Arria 10 FPGA for comparison with earlier FPGA designs: the regular-multiplier version used 9,723 adaptive logic modules and 32 DSP blocks.

The founding decision (1985): reconfigurability at the cost of area. Ross Freeman, co-founder of Xilinx, reasoned that transistor cost was falling quickly enough (Moore's law) to make programmable logic affordable. Designers would obtain custom hardware without the cost and delay of a custom chip, and could correct it after shipping. The XC2064 had 64 configurable logic blocks; current devices have millions.

History

  1. 1978PAL devices (MMI): small programmable logic that replaced the discrete chips connecting larger ones.
  2. 1983–85Altera founded (1983); Xilinx founded (1984) and ships the XC2064 (1985), the first FPGA.
  3. 1990sFPGAs gain on-chip RAM, multipliers and then DSP slices. Used for ASIC prototyping, telecommunications, test equipment and aerospace.
  4. 2011Zynq: ARM processor cores and FPGA fabric on one chip.
  5. 2014Microsoft Catapult: FPGAs deployed in Bing and later Azure servers for search and networking.
  6. 2015 · 2022Intel acquires Altera; AMD acquires Xilinx.

Strengths

  • Custom hardware in small and medium volumes, with no mask cost.
  • Deterministic latency to the clock cycle: networking, trading systems, control loops, broadcast video.
  • Protocols and standards that are still changing; updates after shipping.
  • Prototyping and emulation of a future ASIC before committing to manufacture.

Limitations

  • Compared with an ASIC of the same logic: about 35 times the area, 3–4 times slower and about 14 times the dynamic power for logic-only designs; the area ratio falls to about 18 when the hard DSP and RAM blocks are used (Kuon and Rose, 2007).
  • Unit price from tens to thousands of dollars; too expensive per unit at high volume.
  • Requires hardware design skills (VHDL/Verilog); long build times; difficult debugging.
In video coding and at the industrial partner

The partner's HEVC generation was FPGA-based: a fanless portable encoder built around an FPGA codec. The platform matched the situation: professional volumes in the thousands, an HEVC feature set that was still evolving, and customers who require updates in the field. The thesis corresponds to the next step: when the standard is final and the function fixed, the same kind of design moves to an ASIC, and the design task becomes minimising area, memory and power.

Summary
  1. An FPGA implements a circuit; nothing is fetched or decoded at run time.
  2. It is roughly an order of magnitude larger and more power-hungry than an ASIC, in exchange for no mask cost and reconfigurability.
  3. It is the usual step before an ASIC, and the platform for products that must still change.
Level 4 · ASIC

The ASIC: a circuit fixed at manufacture

An application-specific integrated circuit is designed for one application and manufactured with its own photomasks. It is the most efficient platform and the only one that cannot be modified after manufacture.

How it works

An ASIC contains only the logic the application needs. Each gate is the smallest transistor arrangement for its function, and each wire is a direct metal connection. Compared with the same circuit on an FPGA, it is 5 to 50 times smaller and runs faster at a lower voltage. Memory, pipeline and clock distribution are designed for this circuit alone. This is why a codec block that decodes 4K video at 60 frames per second can consume about ten milliwatts, as the thesis's ALF block does.

The constraint is the development process. From register-transfer-level code to a chip takes one to two years and costs millions in non-recurring engineering: design, verification, licensed IP and masks. An error found after tape-out requires a new set of masks. The function must therefore be final before the design starts. This is why the thesis states in its first sentence that the standard was finalized in July 2020.

The enabling decisions (1980s): structured design and the foundry model. Gate arrays and standard-cell libraries let designers assemble chips from pre-characterised cells rather than individual transistors (the ULA in the 1982 ZX Spectrum; LSI Logic, 1981). In 1987 TSMC opened as a manufacturer that fabricates only other companies' designs, so that companies without a fab could produce custom silicon. Together, these made the ASIC accessible to a company of the partner's size.

History

  1. 1980–82Structured VLSI design (Mead and Conway); gate-array ASICs in consumer products (the ZX Spectrum's ULA).
  2. 1987TSMC founded: companies without factories (NVIDIA, Qualcomm, later Apple's chip division) can produce custom chips.
  3. 1990sSystems on chip: complete products on one die; standard-cell flows with synthesis and place-and-route tools.
  4. 2010Apple A4: a phone manufacturer designs its own SoC.
  5. 2013Bitcoin ASICs: within a year, CPUs, GPUs and FPGAs become uneconomic for mining.
  6. 2016Google's TPU: an ASIC for neural networks in the datacenter. Domain-specific architectures become the industry's response to the end of Moore's law (Hennessy and Patterson, 2018).
  7. 2019–22The industrial partner designs its VVC codec silicon; the thesis delivers its transform and ALF blocks.

Strengths

  • Performance per watt: tens to hundreds of times that of a CPU for the same function (the thesis cites about 20 times the performance at about 20 times lower power; Hameed et al. measured a 500-fold energy difference for H.264).
  • Lowest unit cost and size at volume; integration of a complete system on one die.
  • Deterministic, real-time behaviour; the smallest and lowest-power implementation possible.

Limitations

  • Millions in non-recurring cost and one to two years before the first unit.
  • No flexibility: the function, and the standard, must be final.
  • Risk: a logic error or an unhandled case found after tape-out requires a new set of masks.
  • Requires the volume, or the power and size constraint, that justifies the above.
In the thesis

Every design choice in the explainer is an ASIC design choice: a fixed latency so that blocks chain without stalls, a throughput requirement in samples per cycle derived from 4K60 at 450 MHz, and a systematic accounting of gates, kilobits and milliwatts. Because nothing can be corrected after manufacture, each block was verified bit-exactly against the reference software, over a hundred thousand random vectors and over complete encoded sequences, before the chip was committed.

Summary
  1. Fixing the function at design time yields the highest efficiency.
  2. Economics: non-recurring engineering is paid once; units are the cheapest and lowest-power at volume.
  3. No corrections after manufacture: the standard must be final and the verification exhaustive.
Level 5 · all four platforms

How they are combined: a board, a chip, an appliance

The platforms are complementary. The CPU acts as host; the other platforms are devices under its control. On a PC they are separate cards. In a phone they are blocks on one die. In a professional encoder, the codec chip performs the pixel processing and a small CPU performs control and networking.

How it works

A motherboard connects one host processor to several devices. The CPU boots, runs the operating system and the device drivers, and controls main memory. Each device is attached to a bus (PCIe for expansion cards, the memory bus for DRAM) and usually has its own local memory. Work is delegated by a fixed protocol: the CPU writes a job description, the device reads its input data by direct memory access (DMA), processes it, and raises an interrupt when it has finished. The CPU is free during the operation. This mechanism, called offloading, is the same for a GPU, an FPGA card, a network card and a video capture card.

The limiting resource is usually the bus. PCIe 4.0 ×16 transfers about 32 GB/s in each direction, whereas a GPU's local memory delivers terabytes per second. Efficient systems therefore move data once, process it where it resides, and submit work in large batches.

The decision of the 2000s: heterogeneous computing. Once clock frequency stopped increasing, further gains came from placing specialised engines next to the CPU: GPUs for graphics and later AI, FPGAs for protocols, fixed-function blocks for video, cryptography and radio. Hennessy and Patterson's 2018 Turing lecture described this as the era of domain-specific architectures.

Three systems in which all four platforms coexist

  • A PC or server motherboard. A CPU socket, DRAM slots, and PCIe slots holding a GPU, an FPGA card, a capture card or a network card. Separate chips, separate memories, one bus.
  • A system on chip. A phone or laptop SoC places CPU cores, a GPU, a neural engine, an image signal processor, a modem, a display engine and a video codec engine on one die, sharing one DRAM through an on-chip network. Each block is an ASIC design; the video engine is the consumer form of the blocks the thesis builds.
  • A professional encoder appliance. Video enters over SDI or HDMI, a codec ASIC (an FPGA in the previous generation) compresses it, and a small ARM-based SoC runs Linux, the web interface, rate control and the IP streaming stack. The pixel processing and the control processing are placed on different platforms by design.
Summary
  1. The CPU is the host; every other platform is a device that it controls through a bus.
  2. Data movement, not arithmetic, sets the limits: move data once, process it in place, batch the work.
  3. A system on chip is a motherboard on one die; a modern CPU package is already a small SoC with codec ASIC blocks.

The thesis on this scale

VVC was developed and evaluated in software (the VTM reference model on CPUs). The partner's previous codec generation shipped on FPGAs. The VVC generation moved to an ASIC once the standard was final (July 2020) and the product volumes and power targets required it. The thesis describes the work at that last stage: the function is fixed, so the design problem is area, memory and power at the required number of samples per cycle.

Summary
  1. Final function with volume or power pressure → ASIC; changing function or small volume → FPGA; bulk arithmetic → GPU; everything else → CPU.
  2. Products move along the scale over their lifetime; the host CPU is present at every stage.
  3. The question is not which platform is best, but which platform for which part of the work.
